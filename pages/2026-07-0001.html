Kernel Security

ip_forward = 0 — 보안을 위한 기본 설정

# /etc/sysctl.conf
net.ipv4.ip_forward = 0

# 런타임 확인
$ sysctl net.ipv4.ip_forward
net.ipv4.ip_forward = 0 # 포워딩 끔
net.ipv4.ip_forward = 1 # 포워딩 켬
  • 무엇을 막는가 호스트가 다른 인터페이스 간 IP 패킷을 중계(라우팅)하지 못하게 합니다. 의도하지 않은 트래픽 통과를 줄입니다.
  • 왜 기본값인가 일반 서버는 라우터가 아니므로 포워딩을 끄는 것이 안전한 기본 보안 설정입니다.
  • 컨테이너와의 관계 Docker Bridge가 컨테이너 트래픽을 밖으로 보내려면 보통 포워딩이 필요합니다. 엔진이 필요 시 값을 1로 올릴 수 있습니다.
Incident Timeline

사고 경위

  1. 1
    서비스 유지

    Docker가 ip_forward를 1로 전환

    sysctl.conf에는 ip_forward=0이 적혀 있었습니다. 그러나 Docker Daemon이 최초 실행·재시작될 때 컨테이너 네트워크 구성을 위해 커널의 net.ipv4.ip_forward를 0에서 1로 자동 전환하는 Docker 엔진의 동작 덕분에 서비스 통신에는 지장이 없었습니다.

  2. 2
    접근 제한 잔존

    allow.conf가 사내 접속만 허용한 채 유지

    컴투스 웹개발팀에서 allow.conf로 사내 접속만 허용하였고, 서비스 런칭 후에도 이 상태가 유지되어 장애 상태가 된 것으로 보입니다.

  3. 3
    통신 차단

    sysctl -p로 설정 파일 값이 런타임에 반영

    인프라기술C팀이 장애 지원 과정에서 sysctl -p를 실행하여 sysctl.conf의 ip_forward=0이 런타임에 반영되었습니다. Docker Bridge 아웃바운드 경로가 차단되며, 컨테이너 기반 백엔드 애플리케이션의 DB 연결이 전면 실패하였습니다.
